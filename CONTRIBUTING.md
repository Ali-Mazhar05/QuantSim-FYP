# Contributing to QuantSim

How to stay up to date and ship a change. Everything here is short on purpose; the full
explanation is in the [CI/CD team guide](docs/ci-cd-team-guide.md).

## First time on a new laptop

1. Clone the repository and open **Git Bash** in it.
2. Install **Docker Desktop** and turn on *Start Docker Desktop when you sign in*. Keep at
   least 15 GB free on C:. Recommended settings are in
   [guide section 5](docs/ci-cd-team-guide.md#5-hosting-jenkins-taking-turns).
3. Get the `ci/jenkins/secrets/` folder from Ali over a private channel (never chat or
   git) and run `ci/jenkins/init-env.sh`. It should end with `all secret files present`.
4. Sign in to Jenkins with your **GitHub username** and the password from your line in
   `ci/jenkins/secrets/team_users`.

## Every time you sit down to work

```bash
git switch develop && git pull          # get everyone's merged work
ci/jenkins/host.sh status               # who hosts Jenkins, and its link today
```

- **Nobody hosting?** Run `ci/jenkins/host.sh start` if you will be around for a while;
  otherwise your pushes simply wait for the next host.
- **Working on an existing branch?** Bring it up to date first:
  ```bash
  git switch feature/<name> && git merge origin/develop
  ```
  Pipeline fixes reach your branch only this way. If your branch's Jenkins check fails for
  a reason that has nothing to do with your change, do this before anything else.

## Shipping a change

```bash
git switch -c feature/<short-name>                  # bugfix/<short-name> for a fix
# ...work, then commit with one plain line, no punctuation
.claude/skills/quantsim-git-flow/scripts/preflight.sh
git push -u origin feature/<short-name>
.claude/skills/quantsim-git-flow/scripts/pr.sh      # opens the PR into develop
```

Merge with **Create a merge commit** once the **`continuous-integration/jenkins/pr-merge`**
check is green. That check tests your branch merged into `develop`, which is what will land.
Jenkins then deploys DEV by itself. Details:
[guide section 3](docs/ci-cd-team-guide.md#3-your-everyday-workflow).

Rules that GitHub cannot enforce on our free plan, so we do:
- Never push straight to `develop`, `test`, `acceptance` or `main`.
- Never touch `develop-poc` or `master`.
- Never merge a red PR, never use `--no-verify`, force-push only your own branch with
  `--force-with-lease`.
- Commit messages: one plain line, no punctuation, no "Co-Authored-By" or "Generated by".

## Before you shut down

```bash
ci/jenkins/host.sh stop     # only if you are hosting; hands Jenkins over to the next person
```

Forgetting this makes the next person wait 10 minutes.

## Where to look

| To find out | Look at |
|---|---|
| What each site is running | `/version.json` on it, e.g. https://develop.quantsim-4hz.pages.dev/version.json |
| Why a check failed | **Details** next to the check on the PR (opens the Jenkins log) |
| What changed lately and what was decided | [docs/progress-log.md](docs/progress-log.md) |
| What is planned next | [docs/iteration-plan.md](docs/iteration-plan.md) |
| How to promote, approve, hotfix or roll back | [guide sections 7 and 8](docs/ci-cd-team-guide.md#7-promoting-a-release) |
| Something broke | [guide section 10](docs/ci-cd-team-guide.md#10-when-something-goes-wrong) |
| How the pipeline works inside | [docs/ci-cd.md](docs/ci-cd.md) |

## When something changes for everyone

Whoever makes a change the team must act on also does these:

| Change | Also do |
|---|---|
| New team member, new password or new role (`secrets/team_users`) | Share the updated secrets folder privately; everyone runs `ci/jenkins/init-env.sh`; the host restarts with `host.sh stop` then `start` |
| Any other file in `ci/jenkins/secrets/` | Share the updated folder privately; the host restarts Jenkins |
| Jenkins setup (`ci/jenkins/`) | The host runs `git pull`, then `host.sh stop` and `host.sh start` |
| Something the team must know (a decision, a new rule, a released version) | Add a dated entry to [docs/progress-log.md](docs/progress-log.md) in the same PR |
| How the pipeline or this workflow works | Update this file or the team guide in the same PR |
