QuantSim System Blueprint

Two views of the same platform. The first is the engineering blueprint — every tier, every service, every store, and the technology behind it. The second is the same system with the jargon removed, for an audience that needs to understand what it does and why it is split up at all.

One correction against the reference layout. The six-layer stack you shared — presentation → API → domain services → event backbone → data access → shared data systems — is the arrangement your own ARC document rejects in §4 and §8.2. Two features in particular: a system-wide domain service layer implies the seven domains share one deployment and one data path, and putting Kafka between the domain and the data-access layer puts a log on the path from a service to its own database. This blueprint draws the architecture the document actually settles on — five deployment tiers, eight services, one database each, and Kafka beside the request path. If you present the six-layer version at defense, the first question will be why the diagram disagrees with the spec.
