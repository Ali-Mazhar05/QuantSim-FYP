02The data layer

Five years of minute bars for 5,000 symbols is 2.46 billion rows, roughly 118 GB raw. Total database footprint is near 80 GB, growing about 25 GB a year against 1.92 TB of disk.

Redis 8 for cache and queue

Why Redis rather than Valkey, and when that answer flips The 2024 objection to Redis was licensing: it left open source for RSAL and SSPL, which is what created Valkey in the first place. That objection expired. Redis 8, released May 2025, is tri-licensed and includes AGPLv3, an OSI-approved open-source licence. QuantSim runs stock Redis as an internal cache, does not modify it, and does not resell it as a managed service, so AGPL imposes no practical obligation here.

That makes Redis the better choice for this project on every other axis: universal client libraries, the deepest operational literature, and native data types added to the core in version 8 that this workload actually uses, including time series for the market cache and t-digest for streaming quantiles.

Valkey remains the drop-in escape hatch. It is BSD-3 licensed, Linux Foundation governed, roughly 8% faster with about 20% lower memory use, and is now the default on AWS ElastiCache, Google Memorystore and Debian-family distributions. The wire protocol is identical, so migration is a hostname change. Switch if an institutional customer's procurement blanket-bans AGPL dependencies, which some enterprises do, or if managed Redis pricing becomes the deciding factor at Phase 3.

Two separate Redis instances run, not one. An evicting cache and a durable job queue want opposite memory policies, and combining them means that under memory pressure a queued simulation is silently evicted and a user's run disappears with no error anywhere.

Total working set is under 3 GB against 24 GB provisioned, an eight-fold headroom that absorbs a traffic spike without evicting anything that matters. Hardware at Phase 2 is 2 × AX52, 8 cores and 64 GB each, primary and replica with Sentinel.

What deliberately does not go in Redis Anything that must survive a restart, anything that must be auditable, and anything large. Simulation artifacts go to R2, market history to Timescale, and the audit log to Postgres where it can be queried under oath. Redis holds only rebuildable state, plus the one durable exception of the queue, which is why the queue gets its own instance with its own persistence settings.

What is never written: the raw path tensor A 10,000-path, 252-step, 50-asset simulation in float32 is 10,000 × 252 × 50 × 4 = 504 MB of raw paths. Persisting that per run is unaffordable at any price. The manifest stores the seed and the full configuration instead, which regenerates the run bit-exactly on demand, and only the aggregates a human actually reads are kept. That is a 63-fold reduction, and exact reproducibility from a seed is what the audit requirement wanted in the first place.

06Where the cost goes, module by module

Every module falls into one of three groups, and the group decides what makes it expensive. Analysis modules run on the batch fleet and scale with the size of the work submitted. Serving modules run on the application tier and scale with users and requests. Fixed lines cost the same whether ten people use the platform or ten thousand. Confusing the three is how cost models go wrong.

Monte CarloAnalysis$724 Paths times steps times assets. Linear and embarrassingly parallel.

At 1,000 users nearly half the bill is fixed cost, most of it a market-data subscription that a hundred users would need just as much. That is why Phase 0 runs on free end-of-day feeds: it is the only line that does not shrink when you are small. By 100,000 users the picture has inverted and two thirds of the bill is analysis compute, which is the healthy shape, because analysis compute is what customers are actually paying for.

Inside the analysis fleet

One representative run at paid-tier caps is roughly 60 vCPU-minutes, and batch compute totals $1,810 a month at 10,000 users.

Monte Carlo is the biggest bill; topology is the biggest risk Monte Carlo scales linearly in the number of paths, so doubling the workload doubles the cost and nothing surprising happens. Persistent homology scales roughly cubically in the number of points, so an Institution customer analysing 1,000 assets instead of 100 does not consume 10 times more compute, they consume something closer to 1,000 times more. Cap asset count per run, use a sparse or witness-complex approximation above a few hundred points, and never let the topology module run unbounded on the shared fleet.
Three modules are almost free, and that is a design result rather than luck Trading strategy, stress testing and composite risk together are 6% of batch compute, because all three consume simulation output instead of producing it. Generating paths once and then running twelve stress scenarios, a strategy evaluation and a composite score against the same cached tensor is what keeps a full pipeline at 60 vCPU-minutes. If each of those modules re-ran its own simulation, one pipeline would cost nearer 200 vCPU-minutes and the free tier would not be affordable.

Three risks worth stating

  • Phase 0 rests on Oracle's free tier, which was halved in 2026. The Always Free ARM allocation went from 4 OCPU and 24 GB to 2 and 12, with no announcement, and capacity is regionally unreliable. Keep everything containerised so Phase 0 can move to an $87 rented machine in an afternoon, and treat the free tier as a convenience rather than a foundation.
  • The module estimates are unmeasured. Every figure in section 06, and therefore every fleet size and margin in section 05, comes from the module definitions rather than a profiler. Measure the Monte Carlo and persistent-homology paths before publishing any cap publicly.
  • The free tier is unmetered by design, so abuse is the main scaling risk. Fifty runs a month at 10,000 paths is the cap, but a script can reach it from every account it creates. Gate signup on a verified institutional email or an aged code-hosting account, and rate-limit account creation per address range.
